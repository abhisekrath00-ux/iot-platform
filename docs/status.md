2026-10-20 migration ledger fixes a CI deadlock (local, tip under test): the go job failed on the geofence tip with TestIntegrationAlertLifecycle "cross-tenant comment = 500: deadlock detected (SQLSTATE 40P01)". Reproduced deterministically with two psql sessions and the server log: every test-server construction (and every API boot) re-ran ALL migration files, and a no-op ALTER TABLE still takes ACCESS EXCLUSIVE. File 0011 in one implicit transaction holds ACCESS EXCLUSIVE on alerts (its four no-op ALTERs) and then wants SHARE on alert_comments (CREATE INDEX), while commentAlert's INSERT INTO alert_comments ... SELECT FROM alerts holds ROW EXCLUSIVE on alert_comments and wants ACCESS SHARE on alerts - a textbook two-table cycle, killable on either side. The pg_advisory_lock only serialized migrate-vs-migrate, never migrate-vs-requests; CI runs `go test ./...` with packages in parallel against one database, so a sibling package's re-migration could interleave with cmd/api's alert tests. In production the same cycle was theoretically reachable only while a NEW migration file's DDL overlapped live traffic during a rolling deploy. Fix: internal/migrate records applied files in schema_migrations and skips them - a boot or test setup against a current database takes no DDL locks at all, so the window is gone, not narrowed. Files stay idempotent because an apply or ledger-write failure is not recorded and runs again next boot; ApplyFile force-runs one file for idempotency tests. cmd/mcp's test helper (a second copy of the old loop) now shares the package, and TestIntegrationMigrateIsRepeatableWithVersionedFlows force-applies 0007 to keep its backfill check meaningful. Verified: deterministic two-session repro deadlocks on the old pattern and cannot form once migrate skips applied files; 5 back-to-back migrate passes against a current DB each finish in milliseconds while 40 concurrent comment INSERTs under a 300 ms lock_timeout all succeed (deadlock counter 0); TestSecondMigrateTakesNoDDLLocks guards the skip; full server suite green on fresh DBs both serial (-p 1) and CI-parallel (no -p 1). OPERATIONAL GATE, unchanged by this fix: the first apply of a genuinely new migration on a live multi-replica deploy still takes its DDL locks, so deploys should migrate before serving traffic (the ledger only removes re-run locking, never new-file locking).
